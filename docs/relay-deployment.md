# Relay Deployment

TypeKart internet play uses a WebSocket relay. The relay routes room-scoped protocol envelopes between an authoritative host and joiners. It does not run game rules, store accounts, or perform matchmaking.

## Local Development

Start a local relay:

```sh
cargo run -- relay --bind 127.0.0.1:8080
```

Host through that relay:

```sh
cargo run -- host-online --name host --relay ws://127.0.0.1:8080
```

Join using the room code printed by the host:

```sh
cargo run -- join-online --name player2 --relay ws://127.0.0.1:8080 --room ABCD-1234
```

## Local Network Relay

To let other computers on the same LAN use your relay, bind it to all interfaces:

```sh
cargo run -- relay --bind 0.0.0.0:8080
```

Then host and join using the relay machine's LAN address:

```sh
cargo run -- host-online --name host --relay ws://192.168.1.25:8080
cargo run -- join-online --name player2 --relay ws://192.168.1.25:8080 --room ABCD-1234
```

## Public Relay

For public internet play, run the Rust relay as a plain `ws://` service on localhost and put a TLS reverse proxy in front of it.

Recommended shape:

```text
players -> wss://relay.example.com -> reverse proxy -> ws://127.0.0.1:8080
```

The TypeKart client supports `wss://` relay URLs. The Rust relay binary currently does not terminate TLS directly.

Example public commands:

```sh
cargo run -- host-online --name host --relay wss://relay.example.com
cargo run -- join-online --name player2 --relay wss://relay.example.com --room ABCD-1234
```

## Reverse Proxy

Caddy is the simplest deployment target because it manages certificates automatically:

```caddyfile
relay.example.com {
    reverse_proxy 127.0.0.1:8080
}
```

Run the relay bound only to localhost on the server:

```sh
typekart relay --bind 127.0.0.1:8080
```

## Operational Limits

- The relay is stateful and in-memory. Restarting it closes all rooms.
- Room codes are generated by the relay.
- The host remains authoritative; if the host disconnects, the room closes.
- There is no authentication, moderation, reconnect, spectator mode, or matchmaking.
- Snapshot traffic is currently forwarded at the same rate as LAN play.
- Use a process supervisor such as `systemd`, `launchd`, Docker restart policy, or a platform service manager for long-running deployments.

## Validation Checklist

1. Start `typekart relay --bind 127.0.0.1:8080`.
2. Run `host-online` against `ws://127.0.0.1:8080`.
3. Run `join-online` against the printed room code.
4. Ready both players and start a race.
5. Repeat through a LAN IP from a second machine.
6. Repeat through `wss://` after configuring the public reverse proxy.
